# weather-check

日本国内の任意の地点について、気象庁(JMA)などの公式データをWebFetch/Bashのみで取得し、正確な事実データとして整理する。**ブラウザ（Claude in Chrome）は使わない** — クラウドで完結させ、どのデバイスからでも同じ結果になるようにするため。tenki.jpのようなJavaScriptで内容を描画するサイトはWebFetchで取得すると発表日時がずれた古いキャッシュを返すことがあるため使わない。

このスキルは「データを集めて整理する」ところと、ゆきさん向けの日次ブリーフィングとしての出力までを担当する。呼び出し側（会話中の指示など）が地点や出力体裁を別途指定した場合はそちらを優先し、指定がない場合（`/weather-check` を引数なしで呼ぶ場合を含む）は下記の「デフォルトの呼び出し」に従う。

## Default invocation (no arguments or extra instructions)

これは日常的にはゆきさんの毎日の天気・健康ブリーフィングとして使われる。呼び出し側から地点や出力形式について特に指示がない場合は、次を前提にしてよい：

- **対象地点**: 仙台市（宮城県、府県コード040000、仙台の地点コード34392、緯度38.2682／経度140.8694）。ただし会話の文脈や前回のメモから、ゆきさんが旅行中・滞在先が異なると判断できる場合はその地点に切り替える。判断できなければ仙台のまま実施する。
- **実行環境**: クラウド実行専用。ブラウザ（Claude in Chrome）は使わない。
- **出力フォーマット**: 下記「デフォルトの出力フォーマット」に従う。

## Specify the location

呼び出し側から地点名が与えられたら、気象庁の府県予報区コードと緯度経度を確認する。わからない場合はWebSearchで「気象庁 予報区コード ＋地名」を検索して確認する。このSKILL内の例は宮城県・仙台（府県コード040000、仙台の地点コード34392、緯度38.2682／経度140.8694）を使っている。

## Step 1: Fetch the forecast and temperature

`https://www.jma.go.jp/bosai/forecast/data/forecast/{府県コード}.json` をWebFetchで取得する。

- `reportDatetime` を確認し、本日の日付と一致するか必ずチェックする。
- report[0]（短期予報）のtimeSeries[0]から天気文（weathers）、timeSeries[1]から降水確率（pops）、windsを今日・明日それぞれ抽出する。
- 気温はreport[0]のtimeSeries[2]（対象地点のtemps配列）を使う。**この配列の意味は発表時刻によって決まっている**ので、値をそのまま「最高/最低」と決めつけず、必ず個数と並び順で判定すること:
  - 要素が4つある場合（5時・11時発表など、今日と明日の両方が入っている場合）: `temps[0]`=今日の最高気温、`temps[1]`=今日の最低気温、`temps[2]`=明日の最低気温、`temps[3]`=明日の最高気温。
  - 要素が2つの場合（17時以降の発表など、今日のデータが落ちている場合）: `temps[0]`=明日の最低気温、`temps[1]`=明日の最高気温。この場合、今日の気温は「本日分の気温データはこの時間の発表には含まれていません」と明記し、無理に埋めない。
  - 迷ったらtimeDefinesの日付・時刻を見て、どの値がどの日のものか自分で確認してから使うこと（生成AIによる要約の言い換えに頼らず、値と時刻配列を並べて機械的に対応させる）。
  - 今日の最高気温と最低気温が近い/同じ値になることがある（曇天・降雨で気温差が小さい日など）。異常値に見えても発表データをそのまま採用し、「気温差の小さい一日」のように自然な形で触れる程度でよい。

## Step 2: Fetch warnings and advisories

`https://www.jma.go.jp/bosai/warning/data/warning/{府県コードまたは地方コード}.json` をWebFetchで取得する。

- 発表日時（reportDatetimeまたはheadline内の日時）が本日の日付と一致する場合のみ、発表中の警報・注意報の種類と対象地域を採用する。
- **一致しない場合（数日前や別の月のデータが返ってくることがある）は、この項目自体を省略し、無理に記載しない。** 気象庁のこのエンドポイントはキャッシュにより日付がずれた内容を返すことが確認されているため、日付確認は必須。

## Step 3: Fetch heatstroke alert status

`https://www.wbgt.env.go.jp/alert.php` をWebFetchで取得する。

- ページに表示されている発表日時が本日の日付と一致する場合だけ、対象都道府県のアラート発表状況（発表なし／熱中症警戒アラート／熱中症特別警戒アラート）を採用する。
- 一致しない場合は「熱中症警戒アラートの発表状況は最新化されていなかったため参照できませんでした」と明記する。
- アラートの有無に関わらず、Step1で得た今日・明日それぞれの最高気温をもとに、次の目安で危険度を出す。**これは公式のWBGT実測値ではなく気温からの簡易目安なので、必ず「推定」と分かる表記を付ける**：
  - 35℃以上 → 危険 相当
  - 33℃以上 → 厳重警戒 相当
  - 30℃以上 → 警戒 相当
  - それ未満 → 注意〜安全
- 今日・明日の両方について危険度を出し、表形式でもよい。

## Step 4: Estimate the UV index

気象庁・環境省とも紫外線の常時更新API/ページを提供していないため、以下の目安で今日・明日それぞれ算出する。**実測値ではなく推定であることを必ず明記する。**

季節（月）・天気（晴れ/曇り/雨）・地点のおおよその緯度から目安を出す：
- 夏季（6〜8月）晴天 → 非常に強い〜極端に強い
- 夏季 曇天 → 強い程度（1段階下げる）
- 春・秋 → 中程度〜強い
- 冬季 → 弱い〜中程度
- 緯度が低い（沖縄など）場合は1段階上げる、高い（北海道など）場合は1段階下げる目安で調整する。

ピーク時間帯（10〜14時頃）の外出を避ける、日傘・帽子・日焼け止め（SPF30〜50程度）の目安も添える。

## Step 5: Calculate sunrise and sunset

ネットワークに依存せず、このスキルに同梱のスクリプトで計算する（気象庁・他サイトのページ取得は不要で、常に安定して使える）:

```
python3 <このSKILL.mdと同じディレクトリ>/scripts/sunrise_sunset.py <緯度> <経度> <YYYY-MM-DD> 9
```

例（仙台、今日の日付）:
```
python3 scripts/sunrise_sunset.py 38.2682 140.8694 2026-08-25 9
```

計算値であり実際とは1〜2分程度前後する可能性がある旨を一言添えるとよい。

## Step 6: Heat shock information

外部データ不要。Step1の最低気温と季節（10月〜4月は特に強調）から、入浴時の急激な温度差に注意する旨の具体的なアドバイスを作る。

## Step 7: Other seasonal information (optional, low priority)

花粉（2〜5月）、PM2.5・黄砂（春）、インフルエンザ・感染症（流行期）などは、信頼できる出典が確認できた場合のみ記載する。無理に探しに行かず、確認できなければこの項目自体を省略する。台風情報は現時点で信頼できる構造化データ源が確認できていないため、必要なら呼び出し側の判断でWebSearchを使うこと（このスキルの必須範囲には含めない）。

## Date consistency rules (common to all steps)

- 発表日時・報告日時が本日の日付と一致しないデータは使わない。「本日は情報を取得できませんでした」と明記し、推測で埋めない。
- Step3・Step4の推定値は日付整合性チェックの対象外だが、必ず「推定」と表記する。
- Step2・Step3で使うページは日付がずれたキャッシュを返すことがあるため、必ず発表日時を確認してから使う。

## Information this skill should return

- 今日・明日の天気、最高/最低気温、降水確率、風
- 熱中症: アラート発表状況（取得できた場合）＋気温ベースの危険度目安（推定）
- 紫外線指数の目安（推定）、今日・明日
- 気象警報・注意報（取得でき、日付が一致した場合のみ）
- 日の出・日の入り（計算値）
- ヒートショックに関する季節的な注意点
- （該当あれば）その他の季節情報

呼び出し側が出力の体裁（見出しの付け方・絵文字・文体・締めの一言など）を別途指定した場合はそれに従う。指定がない場合は、次の「デフォルトの出力フォーマット」で最終的な回答をまとめること。

## Default output format (when unspecified)

- 日本語で出力する。
- 絵文字を適度に使って読みやすくする。
- 冒頭に「今日（日付）の仙台 天気ブリーフィング」（地点が異なる場合はその地点名）と明記する。
- 次のセクションを見出しで区切る: 天気予報（今日＋明日）／おすすめの服装／熱中症情報／気象警報注意報（該当あれば）／日の出日の入り／ヒートショック情報／UV・紫外線情報／（該当あれば）その他の季節情報。
- 最後に「一言アドバイス」を1〜2文で締める。
- 簡潔にまとめつつ、行動につながる具体的な情報を優先する。
- 推定値（熱中症の気温ベース目安、紫外線指数の目安）や計算値（日の出日の入り）には必ずその旨（「推定」「計算値」）を分かる表記で付ける。
- データの発表日時が本日と一致しない項目は「本日は情報を取得できませんでした」と明記し、推測で補完しない。
