# Travel Packing Checklist

目的地・日程・移動方法・予定に合わせて、日本語のMarkdownチェックリストを作る。

毎回、vault の次の二つを読む。利用できない場合は独自の持ち物ルールで補わず、ノートの提供または必要な基準の確認を求める。

- `idea_notes/outings/travel/travel-packing.md` — 重量目標、実測台帳、超過時の判断
- `idea_notes/outings/travel/travel-packing-checklist-rules.md` — 品目、選定条件、出力順、出発前確認

飛行機を使う旅行では、さらに `idea_notes/outings/travel/carry-on-weight-limits.md` を読む。航空会社の実運航会社・予約画面の規定が、ノート内の記録より優先する。

## Confirm the trip

会話から確定できない場合だけ、次を確認する。

- 目的地、日付、泊数
- 飛行機の利用、実運航会社、便名または予約画面の手荷物条件
- 宿で洗濯できるか
- 登山・ハイキング、海外渡航など、詳細ルールの条件項目を変える予定

飛行機を使う旅行で実運航会社や予約画面の規定が未確認なら、その確認を出発前タスクに残す。

## Check weather

目的地ごとに旅行日の予報を、一次情報または信頼性の高い予報から確認する。日本国内では気象庁を優先し、最高・最低気温、降水または雨雪、風、警報・注意報を確認する。

- 予報期間内なら、詳細ルールの天候条件に従って必要な品だけを加える。
- 予報期間外なら、確定的な天気として扱わず、再確認時期を明記する。
- 出発直前の天気・警報・交通影響は `$travel-departure-check` で確認する。

## Build the checklist

`travel-packing-checklist-rules.md` の出力構成、常備品、条件品、出発前確認をそのまま適用する。完成品はコピーして使える単一のMarkdown文書とし、持ち物と出発前確認だけを `- [ ]` にする。

条件項目は有無を確定してから該当分だけを出し、チェックリストに「〜の場合」の分岐文を残さない。

### Weight validation

`travel-packing.md` の重量基準と実測台帳に従う。旅行で追加した条件品も実測値を加算し、未計測品が一つでもあれば、合計を暫定と表示して目標を満たすとは判定しない。

- 飛行機を使わない旅行では、通常目標を適用する。
- 飛行機を使う旅行では、実運航会社・予約画面の制限と、該当する重量目標を適用する。
- 飛行機では、重量、寸法、個数、液体物、モバイルバッテリーの条件と、出発前の全バッグ合算計量を必ず出す。小型機では寸法も先に確認する。
- 目標を超えたら、基準ノートの「重量超過時の判断」順に見直す。必携品だけで超える場合は、宅配・預け入れ・航空便または運賃の変更を明示し、必携品を黙って外さない。
