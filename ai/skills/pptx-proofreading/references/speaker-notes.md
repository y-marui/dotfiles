# Speaker notes

speaker note は、次の順序を既定とする。新規作成・修正時の推奨区切りは、校閲対象外であることを明示する `--- メモ（校閲対象外） ---` とする。

```text
発表原稿（校閲対象）

--- メモ（校閲対象外） ---
個人メモ…
```

- speaker noteをスライドに対応付けるときは、`notesSlideN.xml` の番号をスライド番号とみなさず、各 `ppt/slides/_rels/slideN.xml.rels` のnotesSlide relationshipから対応するノートパートを解決する。ノートのないスライドがあると、両者の番号は一致しない。
- 次のいずれかと完全一致する独立行を、既知の区切りとして受け入れる。大文字小文字、全角・半角、空白も含めて完全一致で判定する。
  - `--- メモ（校閲対象外） ---`
  - `---メモ---`
  - `--- メモ ---`
  - `---note---`
  - `--- note ---`
  - `--- note (not for review) ---`
- 既知の区切りが1つだけ存在する場合、その前を発表原稿として校閲する。区切り行とそれ以降のメモは、一切レビュー・編集・引用しない。
- 既知の区切りも区切りらしい独立行もない場合、ノート全体を発表原稿として扱う。
- `---...---` のように区切りらしく見える独立行があるものの既知のパターンと一致しない場合は、境界を推測せず、そのノートを校閲しない。対応するスライドへ `slide_level: true` のコメントを追加し、`Speaker note / 境界:` で始めて、規定済みの区切り行への変更、または意図した形式であれば既知パターンへの追加を促す。
- 既知の区切りが複数ある、区切り行の前後に同じ行の本文があるなど、境界を一意に判定できない場合は、ノートを変更せず「speaker note の原稿・メモ境界を確認してください」と報告する。
- 区切りが正しくても、ノート全体または区切り前が箇条書きの断片、TODO、連絡先、個人的注記、資料リンク、断片的な引用などを主とし、発表原稿よりメモらしい場合は、原稿として校閲してよいか確認する。原稿とメモが混在して見えて範囲を一意に定められない場合も、推測で校閲・編集せず要確認として報告する。
- ノート原稿への提案はノート本文に書き込まず、対応するスライドの `slide_level: true` コメントに残す。コメントは `Speaker note / 原稿:` で始め、対象の現行語句を引用し、具体的な修正案を示す。スライド本文の指摘と同じコメントへ混在させない。
- 出力前にノートXMLを原本と比較し、区切り行とメモ部分が完全に保持されたことを確認する。直接編集をしていない場合も、抽出したノート原稿・メモ境界をレビュー記録として検証する。
