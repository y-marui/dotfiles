# Fact-checking Guide

外部から検証可能な主張を、参照チャットのもっともらしさではなく根拠に基づいて分類する。目的は「全てを真と断定すること」ではなく、確認済み、未確認、推論を読者が区別できるノートにすることである。

## Claim ledger

書く前に、外部事実を主張単位へ分けて次の状態を付ける。複数の主張を一つの引用でまとめて正当化しない。

| 状態 | 意味 | ノートでの扱い |
|---|---|---|
| 確認済み | 直接支える信頼できる資料を確認した | 出典と確認日を付けて記載 |
| 部分確認 | 主張の一部だけ確認できた | 確認できた部分と未確認部分を分ける |
| 未確認 | 根拠へ到達できない、または資料が不足 | 会話内情報として明示するか、結論に不要なら省く |
| 矛盾 | 信頼できる資料同士、または時点違いで食い違う | 両方を残し、日付・条件・追加確認事項を書く |
| 推論 | 資料から導いた評価や仮説 | 根拠と推論であることを明示する |

ユーザー自身の好み、所有物、採用判断は外部事実とは別である。ユーザーの発言として正確に記録し、勝手に一般化しない。

## Source selection

主張が変化し得る、専門的、ニッチ、高ステークス、または参照ページ・論文に依存する場合はwebで確認する。検索結果の要約だけで確定せず、主張の種類に合う資料を選ぶ。

- 現行の制度、仕様、価格、日程、団体自身の説明: 法令、行政、標準化団体、公式データベース、メーカー、主催団体などの一次・公式資料
- ある研究が実際に報告した結果: 出版社版の原著論文、正式なデータ、試験登録、技術文書
- 分野全体の合意、効果、安全性: 現行ガイドライン、系統的レビュー、メタ解析、質の高い査読済みレビュー
- 背景説明または一次資料へ到達できない場合: 信頼できる二次資料。二次資料しかないことを必要に応じて示す

販売ページ、まとめサイト、SNS投稿は、そのページ自身の掲載内容や募集状況の確認には使えるが、科学的効果、安全性、一般的評価の根拠にはしない。AI生成の要約、検索スニペット、別のチャット、出典不明の転載を根拠にしない。

ページを実際に開き、タイトル、発行主体、公開・更新日、主張を支える本文、URLを確認する。リンク先が主張を直接支えない場合は引用しない。URL、DOI、PMID、団体名、商品名、イベント名を推測で組み立てない。

## Time-sensitive claims

価格、販売状況、製品仕様、募集、営業、イベント日程、人事、規則、ソフトウェア仕様などは、保存時点で再確認する。

- 「最新」「現在」を曖昧にせず、絶対日付または「YYYY-MM-DD確認」と書く。
- 古い会話と現行資料が異なる場合は現行情報へ更新し、判断経緯に必要なら旧情報も時点付きで残す。
- 公式情報がなく、SNS等しかない場合は媒体と投稿日を明記し、継続中と推定しない。

## Scientific and technical claims

科学的主張では、論文が存在することと、その論文が当該結論を支持することを別々に確認する。

- 書誌情報: 著者、題名、誌名、年、巻・頁またはarticle number、DOI/PMIDを出版社または正式データベースで照合する。
- 研究内容: 対象、試料、手法、介入または曝露、比較対象、測定結果、研究デザイン、主要な限界を確認する。
- 証拠の強さ: 単一研究、観察研究、in vitro・動物研究、症例報告、preprintを一般化しない。preprint、撤回、訂正、懸念表明の有無を確認する。
- 再現性と整合性: 重要な結論は、可能なら独立した複数資料、レビュー、ガイドラインと照合する。文献間の不一致を消さない。
- 因果関係: 相関、機序仮説、因果効果を区別する。統計的有意差を臨床的・実用的な重要性と同一視しない。
- 適用範囲: 実験条件、材料系、人口集団、用量、期間を越えて結論を拡張しない。

「報告が見つからない」「初めて」「安全」「有効」「証明された」などの包括的主張は、限定した検索範囲と確認日を明記する。検索で見つからなかったことだけを不存在の証明にしない。

医療・健康・安全に関わる高ステークスな内容は、現行ガイドラインや公的情報を優先し、個別の診断・治療判断へ飛躍させない。重大な不確実性が残る場合はノート内に明記する。

## Citation style in the note

- 一般のWeb資料: 主張の直後に、内容を直接支えるMarkdownリンクを置く。
- 学術資料: 本文では著者・年または番号で参照し、末尾に完全な書誌情報とDOI/PMIDへのリンクを置く。
- 同じ出典を広い段落の末尾に一つだけ置いて、段落中の全主張を支えているように見せない。
- 短い原文確認が必要な場合を除き、引用ではなく要約する。
- 元チャットリンクは「元の会話」に分離し、検証資料の一覧へ混ぜない。

## Stop conditions

核心となる主張を検証できず、それを事実として書くと誤解を生む場合は、推測で埋めない。未確認として保存できるならそうし、ユーザーの判断が必要なら作業を止めて不足資料を求める。閲覧できない資料、存在未確認の論文、アクセスできないチャットを読んだことにしない。
